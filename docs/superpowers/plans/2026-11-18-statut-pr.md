# Statut des PR dans Start work — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** chaque PR de l'onglet PR de Start work affiche son statut, `Brouillon · alice` ou `Prête · bob`.

**Architecture:** la règle du libellé va dans un module pur `mods/start-work/github.js` (`prMeta`), testé par node.
`main.js` demande `isDraft` à `gh pr list` et range ce libellé dans `meta`, que le filtre et l'affichage lisent déjà.
Avant la feature, une refacto sans changement de comportement sort de `load()` la fonction interne `gh`.

**Tech Stack:** JavaScript gpui-kit (mod Herdr), `gh`, node pour les tests (`node:assert/strict`).

**Spec:** `docs/superpowers/specs/2026-11-18-statut-pr-design.md`

## Découpage en PR

Fichiers touchés hors tests, spec et plan : `main.js`, `github.js`, `README.md` (3). **Une seule PR**, story unique P1.

## Global Constraints

- Libellés exacts : `Brouillon` (`isDraft: true`), `Prête` (`isDraft: false`), séparateur ` · ` (espace, point médian, espace).
- Auteur absent (`author` null ou `login` vide) : le statut seul, sans séparateur.
- `isDraft` n'est demandé qu'à `gh pr list` : `gh issue list` ne connaît pas ce champ.
- Messages d'erreur de `load()` identiques mot pour mot (refacto).
- Module testable sans import `gpui-kit` ni `herdr` (README : `main.js` ne se charge pas sous node).
- Tests du contexte : `node mods/start-work/jira.test.js`, `node mods/start-work/profile.test.js`,
  `node mods/start-work/github.test.js` (dès la tâche 2), `herdr-app check ~/.config/herdr-app/mods/start-work`.
- Commits : message en français avec gitmoji, terminé par `Co-Authored-By: <modèle de l'implémenteur>`.

## Review Focus

- PR d'un compte supprimé (`author: null`) : `Prête` seul, pas de `Prête · ` ni d'exception → cas 3 de la tâche 2.
- `author.login` vide : même rendu → cas 4 de la tâche 2.
- Onglet Issues après l'ajout d'`isDraft` : doit charger, auteur seul → cas 6 et recette de la tâche 2.
- Compte gh sans accès au repo : les deux messages d'erreur (profil, compte actif) inchangés après la refacto → recette de la tâche 1.
- Largeur de la colonne `meta` avec `Brouillon · un-login-long` : la ligne reste lisible (le titre tronque) → recette de la tâche 2.

- [ ] **Step 2 : `github.js`**

`mods/start-work/github.js`

```javascript
// The columns of a gh list item: its author (meta) and, for a PR, its status (tag).
// Pure, no imports: `node mods/start-work/github.test.js` checks it.
export const prStatus = (pr) => (pr.isDraft ? "Brouillon" : "Prête");

export const authorLogin = (item) => item.author?.login ?? "";

// isDraft is a gh pr field only: gh issue list rejects it.
export const GH_LISTS = {
  pr: { fields: "number,title,author,url,isDraft", meta: authorLogin, tag: prStatus },
  issue: { fields: "number,title,author,url", meta: authorLogin },
};
```

- [ ] **Step 3 : `main.js`**

`loadGh`, la ligne `this.lists[kind] = …` :

```javascript
// Theme color names, so tags follow light and dark mode.
const TAG_COLORS = { Prête: "ansi2", Brouillon: "muted" };
const statusTag = (label, t) => {
  const color = t[TAG_COLORS[label]];
  return h_flex().w(76).flex_none().justify_end()
    .child(div().px(6).rounded(4).border_1().border_color(color).text_size(11).text_color(color).child(label));
};
```

Dans `render()`, après la colonne `meta` de la ligne : `.when(Boolean(i.tag), (el) => el.child(statusTag(i.tag, t)))`.
