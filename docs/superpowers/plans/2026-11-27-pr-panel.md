# Panneau PR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un panneau Herdr à droite qui montre la PR de la branche du terminal focalisé : statut, approbations, relecture demandée, CI, Sonar, retours, description.

**Architecture:** Mod `mods/pr-panel/` en trois fichiers : `pr.js` (règles pures, testées sous node), `load.js` (appels `git`/`gh`, `run` injecté pour les tests), `main.js` (la vue). Il réutilise start-work par import relatif : `profileAccount` (`profile.js`), `myPrMeta`, `isPending`, `prStatus` (`github.js`), `ghCommand`, `json`, `sh` (`run.js`), `originRepo`, `launchAgent`, `openUrl` (`launch.js`).

**Tech Stack:** gpui-kit / herdr (`mods/*/gpui-kit.d.ts`, `herdr.d.ts`), `gh` (REST JSON + GraphQL), tests `node <fichier>.test.js` avec `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-11-27-pr-panel-design.md`

## Global Constraints

- Textes de l'interface en français, vocabulaire de `docs/domaine.md` (Prête, Brouillon, Approbation, Retours, Fil de relecture, Commentaire hors fil, « relire » / « retours »).
- Compte `gh` : `profileAccount(readTextFile("~/.claude/profiles.json"), owner)`, sinon compte actif ; toute commande `gh` passe par `ghCommand(account, args)`.
- Approbations sur `APPROVALS_FOR_QA` (2) via `myPrMeta`.
- Relire lance `/pr <n> review`, Retours `/pr <n> comments`, par `launchAgent("#<n>", space, cwd, task)`.
- Rafraîchissement : changement de `focused().cwd` ou de `focused().terminal`, ↻, et toutes les 120 000 ms si `window()?.visible`.
- Aucune animation par minuteur : l'indicateur de chargement passe par `.frames(...)`.
- Pas de nouvelle dépendance ; `pr.js` et `load.js` n'importent ni `herdr` ni `gpui-kit` (tests sous node).

## Review Focus

1. Branche détachée ou `HEAD` (rebase en cours) : « Pas de branche », pas d'appel `gh pr view HEAD`. → test Task 2.
2. Plusieurs PR pour la branche (une fermée, une ouverte) : seule l'ouverte compte ; `gh pr view <branche>` peut rendre la fermée. → `gh pr list --head <branche> --state open`, test Task 2.
3. Sonar absent ou nommé « SonarQube Code Analysis » / « sonarcloud » : détection insensible à la casse, pas de ligne si absent. → test Task 1.
4. Réponse lente pendant un changement de focus : une réponse arrivée pour l'ancien dossier ne remplace pas la nouvelle. → jeton de requête, Task 3.
5. Description vide ou PR sans relecteur : section Description « Pas de description », Approbations `0/2` sans liste. → test Task 1.

### Task 1: Règles pures de la PR (`pr.js`)

**Files:**
- Create: `mods/pr-panel/pr.js`
- Test: `mods/pr-panel/pr.test.js`

**Interfaces:**
- Consumes: `myPrMeta(reviews)`, `isPending(thread, me)`, `prStatus(pr)` de `../start-work/github.js`.
- Produces:
  - `PR_FIELDS = "number,title,url,isDraft,author,additions,deletions,changedFiles,body,reviews,statusCheckRollup"`
  - `checksOf(rollup) -> { sonar: {state, url} | null, ci: { text, state } | null, open: [{ name, state, url }] }` — `state` ∈ `"ok" | "ko" | "running"` ; `sonar` : premier check dont le nom matche `/sonar/i`, retiré du reste ; `ci.text` comme `summary()` de pr-agents (`"1 en échec · 1 en cours · 2 ✓"`) ; `open` : checks hors Sonar en `ko` puis `running`.
  - `reviewersOf(reviews, author) -> [{ login, state }]` — dernier avis décisif par relecteur (hors `COMMENTED`, `PENDING`, hors auteur), dans l'ordre chronologique.
  - `PR_THREADS_QUERY` : GraphQL `query($owner:String!,$name:String!,$number:Int!)` qui rend `viewer{login}` et `repository.pullRequest` avec `reviewThreads(last:100)` (nœuds : `isResolved`, `path`, `line`, alias `all`/`first`/`last` comme `THREADS_QUERY` de start-work, plus `comments(last:20){nodes{author{login} body}}`) et `comments(last:50){nodes{author{login} body}}`.
  - `feedbackOf(response) -> { me, threads: [{ path, line, pending, comments: [{ author, body }] }], notes: [{ author, body }], pending: number }` — fils en attente d'abord ; `notes` exclut les commentaires dont l'auteur est `me` ; lève une `Error` si `response.data.repository.pullRequest` manque.
  - `panelOf(pr, { me, reviewAsked, feedback }) -> { number, title, url, status, diff, approvals, reviewers, reviewAsked, mine, checks, feedback, body }` — `status = prStatus(pr)`, `diff = "+<additions> −<deletions> · <changedFiles> fichiers"`, `approvals = myPrMeta(pr.reviews)`, `mine = author.login` égal à `me` (casse ignorée), `reviewAsked` forcé à `false` si `mine`, `body` = corps nettoyé ou `null` si vide ; `feedback` peut valoir `null` (fils non lus) et passe tel quel ; `checks = checksOf(pr.statusCheckRollup)`, `reviewers = reviewersOf(pr.reviews, author.login)`.

```js
// Run: node mods/pr-panel/pr.test.js
const roll = [
  { __typename: "CheckRun", name: "SonarQube Code Analysis", conclusion: "FAILURE", detailsUrl: "s" },
  { __typename: "StatusContext", context: "continuous-integration/jenkins/pr-merge", state: "PENDING", targetUrl: "j" },
  { __typename: "CheckRun", name: "lint", conclusion: "SUCCESS" },
  { __typename: "CheckRun", name: "test", conclusion: "FAILURE", detailsUrl: "t" },
];
assert.deepEqual(checksOf(roll).sonar, { state: "ko", url: "s" });
assert.deepEqual(checksOf(roll).ci, { text: "1 en échec · 1 en cours · 1 ✓", state: "ko" });
assert.deepEqual(checksOf(roll).open.map((c) => c.name), ["test", "continuous-integration/jenkins/pr-merge"]);
assert.equal(checksOf([{ name: "sonarcloud", conclusion: "SUCCESS" }]).sonar.state, "ok");
assert.deepEqual(checksOf([]), { sonar: null, ci: null, open: [] });
assert.deepEqual(checksOf(null), { sonar: null, ci: null, open: [] });

const rv = (login, state, t) => ({ author: { login }, state, submittedAt: t });
assert.deepEqual(reviewersOf([rv("alice", "APPROVED", "1"), rv("bob", "CHANGES_REQUESTED", "2"), rv("alice", "COMMENTED", "3"), rv("me", "APPROVED", "4")], "me"),
  [{ login: "alice", state: "APPROVED" }, { login: "bob", state: "CHANGES_REQUESTED" }]);
assert.deepEqual(reviewersOf([], "me"), []);

// feedbackOf : un fil en attente (alice), un résolu, une note de bob, une note de moi ignorée
const th = (resolved, who, last, path) => ({ isResolved: resolved, path, line: 3, all: { totalCount: 1 },
  first: { nodes: [{ author: { __typename: "User", login: who } }] }, last: { nodes: [{ author: { login: last } }] },
  comments: { nodes: [{ author: { login: who }, body: "x" }] } });
const resp = { data: { viewer: { login: "me" }, repository: { pullRequest: {
  reviewThreads: { nodes: [th(true, "carol", "carol", "a.js"), th(false, "alice", "alice", "b.js")] },
  comments: { nodes: [{ author: { login: "bob" }, body: "et le test ?" }, { author: { login: "me" }, body: "ok" }] } } } } };
const fb = feedbackOf(resp);
assert.equal(fb.me, "me");
assert.deepEqual(fb.threads.map((t) => [t.path, t.pending]), [["b.js", true], ["a.js", false]]);
assert.deepEqual(fb.notes, [{ author: "bob", body: "et le test ?" }]);
assert.equal(fb.pending, 1);
assert.throws(() => feedbackOf({ data: {} }));

const pr = { number: 482, title: "t", url: "u", isDraft: false, author: { login: "Me" }, additions: 120, deletions: 34,
  changedFiles: 6, body: "  ", reviews: [], statusCheckRollup: [] };
const p = panelOf(pr, { me: "me", reviewAsked: true, feedback: fb });
assert.equal(p.status, "Prête");
assert.equal(p.diff, "+120 −34 · 6 fichiers");
assert.equal(p.approvals, "0/2");
assert.equal(p.mine, true);
assert.equal(p.reviewAsked, false); // jamais sur ma propre PR
assert.equal(p.body, null);
```

### Task 2: Chargement de la PR (`load.js`)

**Files:**
- Create: `mods/pr-panel/load.js`
- Test: `mods/pr-panel/load.test.js`

**Interfaces:**
- Consumes: Task 1 (`PR_FIELDS`, `PR_THREADS_QUERY`, `feedbackOf`, `panelOf`), `profileAccount` (`../start-work/profile.js`). `run.js` et `launch.js` importent `herdr` : on déplace leurs morceaux purs dans `../start-work/profile.js`, avec réexport depuis l'ancien fichier pour que leurs appelants ne changent pas :
  - `GH_AS` et `ghCommand(account, args)` (de `run.js`) ;
  - `githubRepo(url) -> "owner/name" | null` : la regex de `originRepo` (`/github\.com[:/]([^/]+\/[^/]+?)(?:\.git)?$/`), que `originRepo` appelle désormais.
- Produces: `loadPanel({ cwd, run, profiles }) -> Promise<{ kind: "none" | "nobranch" | "nopr" | "pr" | "error", message?, branch?, repo?, panel? }>`
  - `run(cmd, args, opts) -> Promise<{ code, stdout, stderr }>` injecté (en vrai : `exec` de herdr avec `{ cwd, on }`).
  - `profiles` : texte de `~/.claude/profiles.json` ou `null`.
  - Étapes : `git remote get-url origin` (échec ou `githubRepo` nul → `none`) ; `git branch --show-current` (vide → `nobranch`) ; `gh pr list --repo R --head B --state open --json <PR_FIELDS> --limit 1` (liste vide → `nopr`) ; en parallèle `gh pr list --repo R --head B --state open --search review-requested:@me --json number --limit 1` (non vide → `reviewAsked`) et `gh api graphql -f query=<PR_THREADS_QUERY> -F owner=… -F name=… -F number=<n>`.
  - Un `gh` en échec rend `kind: "error"` avec la première ligne de stderr ; l'échec de la seule requête des fils garde le panneau avec `feedback: null` (section Retours « Retours non lus »).
